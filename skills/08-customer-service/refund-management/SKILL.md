# refund-management · 退款流程

## 用途
- 评估退款合理性
- 生成退款建议
- 提供客服话术
- 记录退款原因和金额

## 触发场景
- 客户要求退款
- 退货申请需要审核
- 需要判断重发或退款
- 退款纠纷处理

## 输入
- 客户请求
- 订单信息
- 退货原因
- 产品问题证据
- 退款政策

## 输出
```markdown
## 退款处理建议

### 退款合理性评估
### 建议方案
### 客服话术
### 需升级事项
### 记录与统计
```

## 工作流
1. **核实订单**：金额、时间、物流状态
2. **评估原因**：产品质量、物流损坏、不喜欢
3. **匹配政策**：是否在规定期限内
4. **生成方案**：全额退、部分退、换货、重发
5. **输出话术**：专业、共情、明确
6. **标记升级**：大额、欺诈、法律风险

## 调用关系
**被调用**：customer-support

**调用**：complaint-analysis、odoo-integration

## 依赖工具 / Memory
- Tool: 订单系统、退款政策
- Memory: 历史退款案例、欺诈模式

## 边界与限制
- 只生成建议，不自动退款
- 所有退款需人工确认
- 不处理疑似欺诈（需升级）

## 示例
输出：客户因产品质量问题要求退款，建议全额退款并承担退货运费，话术已生成，需客服主管确认
